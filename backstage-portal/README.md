# backstage-portal

The developer portal of the [k8s-sre-platform](https://github.com/krishnakant888/k8s-sre-platform): a [Backstage](https://backstage.io) app with a catalog of everything the platform runs, live views on each component, and a template for a new service that already fits the platform.

This repo holds the **app** (plugins, the three cards, the template) and builds the container image. How it runs on the platform (Deployment, Postgres, route, catalog, access to the clusters) is in the platform repo, `gitops/backstage`, and `docs/portal.md` there.

## What is in it

| | |
|---|---|
| Catalog | Reads the platform's catalog (mounted into the pod from the platform repo). |
| Kubernetes tab | `@backstage/plugin-kubernetes`: pods and deployments of a component in the three clusters. |
| Cards on a component page | `packages/app/src/modules/platform/`: **Argo CD** (sync and health of the application in `argocd/app-name`), **Grafana alerts** (firing alerts matching `grafana/alert-label-selector`) and **RCA reports** (reports the SRE agent wrote for the component). They call the backend proxy (`/argocd`, `/grafana`, `/rca`), which adds the token or login, so nothing secret reaches the browser. |
| Cards on a component page (more) | **Resources** (CPU and memory used against requested and limit, with right-sizing hints, from Mimir) and **Scorecard** (owner, runbook, Argo CD health, own alert rule, dashboard, memory limit, replicas, PodDisruptionBudget), both through the same proxy. |
| Template: new service | `templates/new-service/`: generates the Deployment, Service, HTTPRoute, PodDisruptionBudget, the Argo CD application and the catalog entry, compliant with the platform's Kyverno policies, Pod Security restricted and the gateway, and opens the pull request (`publish:github:pull-request`). |
| Templates: self-service | `templates/*` generated by `tools/gen_templates.py`: scale, resources, environment variable, image tag, roll back, host name, promote to demo, alert, dashboard, sandbox namespace, read-only access, failure drill. Each starts the `selfservice` workflow of the platform repo (`github:actions:dispatch`), which opens a pull request. |
| TechDocs | The docs of a component are built with mkdocs (installed in the image) from its GitHub source when first opened. |
| Sign-in | Guest, read-only (local use). |

The frontend is the new Backstage frontend system; the cards are small extensions (`EntityCardBlueprint`) of the catalog plugin. They are written on the proxy instead of third-party plugins, which do not all support the new frontend system yet.

## GitHub token

The self-service templates and the new-service pull request use `integrations.github` with `${GITHUB_TOKEN}`. The token is optional: without it the portal works and a template reports the GitHub error. See `docs/self-service.md` in the platform repo for what it needs.

## Build the image

Needs Node 24 and Docker. The host build steps come first, then the image (see `packages/backend/Dockerfile`):

```bash
yarn install --immutable
yarn tsc
yarn build:backend
docker build -t ghcr.io/krishnakant888/backstage-portal:0.1.0 -f packages/backend/Dockerfile .
```

`packages/backend/Dockerfile.local` is the same file without BuildKit cache mounts, for a Docker without `buildx`.

CI (`.github/workflows/image.yaml`) builds the image on every push and publishes `ghcr.io/<owner>/backstage-portal:sha-<commit>` from `main`. Where ghcr.io is slow to download from, load the locally built image into the cluster instead:

```bash
kind load docker-image ghcr.io/krishnakant888/backstage-portal:0.1.0 --name gitops
```

## Run it on its own

The image reads `app-config.yaml` and `app-config.production.yaml`; the platform adds its own config on top. To try it without the platform, give it an in-memory database and a catalog:

```bash
docker run --rm -p 7007:7007 -v $PWD/local.yaml:/config/local.yaml -v /path/to/catalog:/catalog:ro \
  -e POSTGRES_HOST=x -e POSTGRES_PORT=5432 -e POSTGRES_USER=x -e POSTGRES_PASSWORD=x \
  ghcr.io/krishnakant888/backstage-portal:0.1.0 \
  node packages/backend --config app-config.yaml --config app-config.production.yaml --config /config/local.yaml
```

with `local.yaml` setting `backend.database` to `{client: better-sqlite3, connection: ':memory:'}`, `auth.providers.guest.dangerouslyAllowOutsideDevelopment: true` and `catalog.locations` to `/catalog/all.yaml`.
